# 视频审阅质量标准

版本：`0.3.0`

领域基线：`video-production-director 0.5.0`

## 1. 目标

审阅标准要同时做到三件事：

1. 找出现在成片中的真实问题；
2. 判断问题属于项目、路线、模型还是跨路线原则；
3. 让修复结果可回归、可复现、可比较，避免把新的问题当作优化。

标准只保留会改变判断的内容。不要为了完整而给每个维度制造问题；干净样片
通过也是有效结果。

## 2. 证据等级

- `E0`：假设，无当前文件证据；
- `E1`：当前文件可复现，有直接观察；
- `E2`：有可复现测量的确定性事实；
- `E3`：不同内容/路线重复出现同一机制；
- `E4`：正例、反例、holdout 和成本比较后证明净收益。

发现记录至少需要 `E1`；稳定规则通常需要 `E3` 或确定性结构约束；未经
`E4` 不得声称普遍优越。

## 3. 证据域

1. 最终成片优先于代理视频、animatic、源码断言、日志或历史报告。
2. 交付尺寸判断影响，原生分辨率判断细节。
3. 连续帧或真实播放判断运动，单帧判断局部静态外观。
4. 技术测量判断文件事实，不直接判断审美或意图。
5. 旧结论只用于导航，每次都重新绑定当前哈希。
6. 未检查、工具缺失、代理压缩和不可听审都必须显式记录。

## 4. 与生成侧的分工

- 生成 Skill：提供意图、稳定锚点、控制路线、有意选择、技术证据和修复。
- 审阅 Skill：提供独立观察、缺陷判定、变更请求和回归结论。
- 用户：提供业务/审美接受、预算和最终责任。

审阅 Skill 不能因为“生成 Skill 已通过”而通过；生成 Skill 不能因为
“审阅 Skill 提了意见”就直接修改，必须有证据和回归。

## 5. 审阅维度

扫描下列维度，只报告实际有效的问题：

### 5.1 合同与指令

- 必需主体/动作/事件是否出现；
- 禁止内容和事实错误；
- 时长、画幅、fps、音频、字幕、平台和安全区；
- 用户明确要求与有意风格是否被保留。

### 5.2 内容与身份

- 主体身份、形态、材质、颜色和产品真实性；
- 多镜头身份和状态连续性；
- 错误主体、形象漂移、产品变形、状态丢失；
- 事实或叙事含义是否被画面改变。

### 5.3 空间、物理与图层

- 支撑、接触、水线、遮挡、穿透、融合、碰撞和分离；
- 前景、中景、背景的遮挡和视差；
- 阴影、反射、折射、透明度、matte、景深和混合边缘；
- 空间关系是否明确声明的写实、风格化或超现实。

### 5.4 运动与时序

- 动作开始、完成和结束状态；
- 方向、速度、节拍、加速和动机；
- 关节、布料、流体、刚体和相机；
- 周期图案的帧率混叠；
- 细线、高光、透明物和遮罩的逐帧稳定；
- 局部跳变、冻结、闪烁、回卷和不可剪辑。

### 5.5 文字与版式

- 逐字内容、字形、字体回退、断行、裁切和安全区；
- 对比、字号、阅读顺序和层级；
- 文字与装饰线、图形、人物、产品、UI 或其他文字的互动；
- 目标尺寸、低光、运动模糊和背景干扰下的可读性。

文字分为两个独立验收：

1. `content_and_glyph`；
2. `layout_and_relationship`。

任一缺失都意味着文字审阅不完整。

### 5.6 编辑与叙事

- 首个可读信息、注意力和信息增量；
- 节奏、停顿、转场、因果和回报；
- 信息是否被美丽画面掩盖；
- 是否可剪辑、可重排、可替换和可交付。

### 5.7 音频与声画

- 流、响度、真峰值、静音和削波；
- 旁白可懂度、音乐层级、效果声功能；
- 对白/口型、动作/音效、节拍/剪辑、字幕/语音；
- 黑场、静音和冻结是否与意图一致。

### 5.8 权利、安全与真实性

- 授权、肖像、音乐、字体、商标和 AI 披露；
- 误导性产品、事实或安全信息；
- 平台和政策硬性要求。

## 6. 关系优先

规则描述关系类型、对象角色和触发条件，不保留主体专用词：

- 周期运动 + 支撑面平移 + 交付帧率；
- 多层元素 + 相对运动 + 局部遮挡；
- 漂浮物 + 局部液面 + 水线；
- 透明图元 + 组级 alpha + 循环边界；
- 连续线条 + 阈值 + 时序采样；
- 文字 + 图形 + 版式层级；
- 声音层 + 语义权重 + 时间对齐。

项目内容可以保留具体主体；核心规则必须能去掉专有名词后仍成立。

## 7. 重叠合理性

重叠不是缺陷。判定顺序：

1. 是设计、叙事、信息、物理还是偶然形成？
2. 前后关系是否有依据并在作品中稳定？
3. 是否保留必要内容、文字、标识、安全和核心动作？
4. 是否提高层次、强调、节奏、空间或情绪？
5. 在目标尺寸和交付时间上是否清楚且一致？
6. 是否把错误转移到边缘、阴影、景深、闪烁或另一处遮挡？

状态：

- `intentional-supported`：意图明确、关系可读、必要信息保留；
- `intentional-ambiguous`：可能有意，但执行不清楚；
- `accidental-harmful`：无功能、冲突或不稳定地破坏必要信息；
- `insufficient-evidence`：无法判断意图或结果。

同一方法适用于文字、产品、人物、透明、遮挡、声音和运动轨迹。规则只禁止
“未声明且产生负面后果的重叠”，不禁止重叠本身。

## 8. 问题记录

```text
issue_id
anchor
media_sha256
timecode / frames
observed
expected_source
intent_or_overlap_judgment
verdict
severity
confidence
evidence
relationship_primitive
scope
rule_ids
status
supersedes
```

`verdict`：`confirmed`、`conditionally_confirmed`、`not_reproduced`、
`insufficient_evidence`。

`severity`：`blocker`、`major`、`minor`、`note`。

`confidence`：`high`、`medium`、`low`。

`scope`：`project-specific`、`route-specific`、`model-specific`、
`conditional-core`、`unconditional-core`。

## 9. 严重度

- `blocker`：文件、核心内容、权利、安全或必须项不可交付；
- `major`：正常发布前必须修复或有责任方豁免；
- `minor`：效益比合理时修复，或记录后交付；
- `note`：观察、风险、主观改进，不自动阻塞。

严重度由影响和证据决定，不由审阅者的语气决定。

## 10. 基准与误报控制

每次规则回归应包含：

- 原始失败案例；
- 至少两个不同内容的同机制案例；
- 至少一个不同生产路线；
- 至少一个高复杂度相机/运动/遮挡案例；
- 至少一个已知干净样片，作为误报基准；
- 至少一个有意风格化/透明/重叠/黑场/静音反例；
- 至少一个不应触发的普通场景。

不得用 best-of-N 证明改进。随机生成需要固定提示、参考、模型、时长、规格
和输出数，比较全部候选的通过率、最差结果、成本和延迟。

## 11. 协同进化指标

至少比较：

- 目标缺陷发生率；
- blocker/major 数量；
- 假阳性和误阻塞率；
- 身份、动作、相机、物理、文字、音频正确性；
- 时序稳定性、可剪辑性和可用片段比例；
- 创意多样性和合理风格豁免；
- 生成时间、重生成次数、算力和人工修复成本；
- 规则覆盖和证据完整性。

候选只有在目标问题明显下降、其他关键质量没有明显下降、反例不被误阻塞且
总成本可接受时，才算净收益。

## 12. 规则生命周期

```text
observed -> candidate -> project-specific / route-specific / model-specific
         -> conditional-core -> unconditional-core
         or rejected / merged
```

规则状态：

- `active`：当前执行中的流程或已知硬约束；
- `candidate`：有证据，但还未完成回归；
- `validated`：已完成声明的回归；
- `rejected`：收益不足或误伤严重；
- `merged`：与已有规则合并。

复核必须追加新 revision，禁止覆盖历史。

规则还必须声明类型：

- `process-invariant`：哈希、版本、独立审阅等流程硬约束，可直接由程序
  强制执行，不要求视频回归样本；
- `quality-heuristic`：遮挡、物理、运动、版式等判断规则，只要超出
  `project-specific`，就必须通过匹配作用域的正例、反例、干净对照和 holdout
  才能保持 `active` 或标记 `validated`。

不得用流程规则的标准替代视觉规则验证，也不得用一条流程规则掩盖某个视觉
启发式尚未回归的事实。

## 13. 负面优化检查

每条建议都要回答：

- 是否会让提示词过长或冲突；
- 是否误伤正常运动、遮挡、透明或创意；
- 是否降低动作幅度、镜头自由或艺术多样性；
- 是否只在某模型/路线有效；
- 是否把缺陷转移到阴影、边缘、景深、时序或其他层；
- 是否增加生成次数、时长、算力、版权或人工成本；
- 是否增加 QA 假阻塞；
- 是否与已有规则重复或无法测试。

若无法证明扩大范围后的净收益，缩小作用域或拒绝。

## 14. 当前原则

1. 审阅先于用户提示，但用户校准可以改变判断。
2. 最终输出证据优先。
3. 文字内容与图文关系分开。
4. 重叠按合理性判断。
5. 先抽象关系，再扩展场景。
6. 单案例不升级全局规则。
7. 生成与审阅不自我通过。
8. 修复必须有原失败、干净对照和反例回归。
9. 规则和问题修订保留历史。
10. 直接、诚实、可证伪，优于“看起来好像有问题”。
11. 变更响应只是生成侧提案，必须再由独立审阅检查新字节。
12. 质量启发式和流程不变量使用不同的证据与验证门槛。
